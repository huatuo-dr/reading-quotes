# reading-quotes 部署指导

域名示例：`read.huatuo.cloud`。仓库：`https://github.com/huatuo-dr/reading-quotes`（公开）。

本文**端口示例一律使用 `3005`**（写入 `.env` 的 `PORT=3005`，Nginx `proxy_pass` 与安全组说明均按此端口）。应用只应监听本机 `127.0.0.1:3005`，公网通过 80/443 由 Nginx 反代。

---

## 1. 腾讯云控制台准备

下列路径以腾讯云控制台当前中文界面为准（若菜单改名，按「云服务器 / 安全组 / DNS 解析」相近入口查找）。

### 1.1 新建或选用 CVM

1. 打开 [腾讯云控制台](https://console.cloud.tencent.com/) → **云服务器 CVM** → **实例**。
2. **已有机器**：记下**公网 IP**、登录方式（密码或 SSH 密钥），跳到「安全组」。
3. **新建机器**：
   - 点击 **新建实例**。
   - **地域**：选离你近的地域（与后续域名解析无关，但影响延迟）。
   - **实例**：轻量即可（2 核 2G 起步足够本应用）。
   - **镜像**：公共镜像 → **Ubuntu Server 22.04 LTS 64 位**（或更新的 LTS）。
   - **存储**：系统盘默认即可。
   - **网络**：勾选分配**公网 IP**（或绑定弹性公网 IP）。
   - **安全组**：可先选「新建安全组」或稍后再改（见下一节）。
   - **登录**：设置 root/ubuntu 密码，或绑定 SSH 密钥（推荐密钥）。
   - 确认订单并开通，等待状态变为**运行中**，复制**公网 IP**。

### 1.2 安全组放行

1. 在实例列表点实例 ID → **安全组** → 点击关联的安全组 ID。
2. **入站规则** → **添加规则**：

| 协议 | 端口 | 来源 | 用途 |
|------|------|------|------|
| TCP | 22 | 建议限你的办公 IP；调试期可 `0.0.0.0/0` | SSH |
| TCP | 80 | `0.0.0.0/0` | HTTP（certbot 校验与跳转） |
| TCP | 443 | `0.0.0.0/0` | HTTPS |

3. **不要**对公网放行 `3005`（应用只给本机 Nginx 访问）。若临时直连调试，可临时加 `TCP:3005` 来源限你的 IP，用完删除。
4. 出站规则保持默认放行即可（需访问 GitHub、Let’s Encrypt）。

### 1.3 域名解析（`read.huatuo.cloud`）

1. 控制台 → **DNS 解析 DNSPod**（或你注册域名所用的解析产品）→ 找到 `huatuo.cloud`。
2. **添加记录**：
   - 主机记录：`read`
   - 记录类型：`A`
   - 记录值：CVM **公网 IP**
   - TTL：默认（如 600）
3. 保存后，本机执行 `ping read.huatuo.cloud` 或 `dig +short read.huatuo.cloud`，应返回该公网 IP。未生效前不要申请证书。

## 2. 服务器软件准备

SSH 登录（用户名按镜像，常见为 `ubuntu` 或 `root`）：

```bash
ssh ubuntu@你的公网IP
```

安装 Node.js 20+、npm、git、Nginx（示例用 NodeSource）：

```bash
sudo apt update
sudo apt install -y git nginx curl
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs
node -v   # 应 ≥ 20
npm -v
```

---

## 3. Clone 与配置

```bash
sudo mkdir -p /opt
sudo chown "$USER":"$USER" /opt
cd /opt
git clone https://github.com/huatuo-dr/reading-quotes.git
cd reading-quotes
cp .env.example .env
nano .env
```

必填（生产示例）：

| 变量 | 说明 |
|------|------|
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | 后台登录 |
| `SESSION_SECRET` | 长随机串 |
| `GIT_TOKEN` | 有本仓 `contents:write` 的 GitHub PAT |
| `GIT_ENABLED` | 生产保持 `true` |
| `GIT_BRANCH` | 默认 `main` |
| `PORT` | **本指导示例：`3005`** |

可选：`GIT_REMOTE_URL`、`GIT_USER_NAME`、`GIT_USER_EMAIL`。

> 不要把 `.env` 提交进 Git。

---

## 4. 一键部署

```bash
cd /opt/reading-quotes
./deploy.sh
```

脚本会：`npm install` → `npm run build` → 后台启动服务（监听 `.env` 中的 `PORT`，示例为 **3005**）。

查看日志：

```bash
tail -f logs/app.log
```

本机自检：

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:3005/
```

应返回 `200`。

## 5. Nginx 反代（HTTP）

先写仅 80 端口的站点配置（证书步骤见下一节）：

```bash
sudo nano /etc/nginx/sites-available/reading-quotes
```

内容示例：

```nginx
server {
  listen 80;
  server_name read.huatuo.cloud;

  location / {
    proxy_pass http://127.0.0.1:3005;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
  }
}
```

启用并重载：

```bash
sudo ln -sf /etc/nginx/sites-available/reading-quotes /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx
```

浏览器访问 `http://read.huatuo.cloud` 应能打开首页（此时仍是 HTTP）。

## 6. HTTPS：用 certbot 申请证书

前提（缺一不可）：

- 域名 `read.huatuo.cloud` 已解析到本机公网 IP  
- 安全组已放行 **80**（Let’s Encrypt HTTP-01 校验要用）  
- Nginx 已按上一节配置好 `server_name`，且 `nginx -t` 通过  

### 6.1 安装 certbot

```bash
sudo apt update
sudo apt install -y certbot python3-certbot-nginx
```

### 6.2 一键申请并写入 Nginx

```bash
sudo certbot --nginx -d read.huatuo.cloud
```

按提示：

1. 输入邮箱（用于到期提醒）  
2. 同意服务条款  
3. 是否分享邮箱可选  
4. certbot 会改 Nginx 配置：增加 443、证书路径，并通常把 80 跳到 HTTPS  

完成后访问：`https://read.huatuo.cloud`。

查看证书状态：

```bash
sudo certbot certificates
```

### 6.3 自动续期

Ubuntu 包装好的 certbot 一般带 systemd timer。检查：

```bash
sudo systemctl list-timers | grep certbot
# 或手动干跑：
sudo certbot renew --dry-run
```

续期成功后无需手工改 Nginx；失败时看 `/var/log/letsencrypt/letsencrypt.log`。

### 6.4 常见失败与处理

| 现象 | 处理 |
|------|------|
| Failed to connect / Connection refused on :80 | 安全组未放行 80；或 Nginx 未在跑：`sudo systemctl status nginx` |
| DNS problem / unauthorized | 解析未指向本机；`dig +short read.huatuo.cloud` 核对公网 IP |
| Too many certificates | Let’s Encrypt 有频率限制，稍后再试或用已有证书 |
| 证书好了但站点仍 HTTP | 确认 certbot 已改站点配置；`sudo nginx -t && sudo systemctl reload nginx` |
| HTTPS 打不开、HTTP 正常 | 安全组是否放行 **443** |

本仓库的 `deploy.sh` **不**申请证书、不改 DNS。

## 7. 更新代码

```bash
cd /opt/reading-quotes
git pull
./deploy.sh
```

网页增删改会改 `data/quotes.json` 并自动 push；`git pull` 前若有冲突需手工处理（见排障）。

## 8. 排障

| 现象 | 处理 |
|------|------|
| 无法登录 | 检查 `.env` 用户名密码；Cookie 是否被 HTTPS/域名策略拦截 |
| Git 同步失败 | 后台点「重试同步」；检查 `GIT_TOKEN` 权限与分支保护 |
| push 冲突 | SSH 上 `git status` / `git pull --rebase` 后重试同步；避免 force |
| 端口占用 | 改 `PORT` 或结束旧 PID（`logs/app.pid`）；示例端口为 **3005** |
| 外网打不开但本机 `curl 127.0.0.1:3005` 正常 | 查 Nginx 与安全组 80/443，而不是对公网暴露 3005 |

---

## 9. 安全提示

服务器持有可写 token；请使用**最小权限** PAT，并保护后台密码。登录被盗意味着仓库可能被改写摘抄文件。不要把 `3005` 对公网长期开放。
