# reading-quotes 部署指导

域名示例：`read.huatuo.cloud`。仓库：`https://github.com/huatuo-dr/reading-quotes`（公开）。

本文**端口示例一律使用 `3005`**（写入 `.env` 的 `PORT=3005`，Nginx `proxy_pass` 与安全组说明均按此端口）。应用只应监听本机 `127.0.0.1:3005`，公网通过 80/443 由 Nginx 反代。

---

## 1. 腾讯云控制台准备

下列路径以腾讯云控制台当前中文界面为准（若菜单改名，按「云服务器 / 安全组 / DNS 解析」相近入口查找）。

### 1.1 新建或选用 CVM

1. 打开 [腾讯云控制台](https://console.cloud.tencent.com/) → **云服务器 CVM** → **实例**。
2. **已有机器**：记下**公网 IP**、登录方式（密码或 SSH 密钥），跳到「安全组」。
3. **新建机器**：
   - 点击 **新建实例**。
   - **地域**：选离你近的地域（与后续域名解析无关，但影响延迟）。
   - **实例**：轻量即可（2 核 2G 起步足够本应用）。
   - **镜像**：公共镜像 → **Ubuntu Server 22.04 LTS 64 位**（或更新的 LTS）。
   - **存储**：系统盘默认即可。
   - **网络**：勾选分配**公网 IP**（或绑定弹性公网 IP）。
   - **安全组**：可先选「新建安全组」或稍后再改（见下一节）。
   - **登录**：设置 root/ubuntu 密码，或绑定 SSH 密钥（推荐密钥）。
   - 确认订单并开通，等待状态变为**运行中**，复制**公网 IP**。

### 1.2 安全组放行

1. 在实例列表点实例 ID → **安全组** → 点击关联的安全组 ID。
2. **入站规则** → **添加规则**：

| 协议 | 端口 | 来源 | 用途 |
|------|------|------|------|
| TCP | 22 | 建议限你的办公 IP；调试期可 `0.0.0.0/0` | SSH |
| TCP | 80 | `0.0.0.0/0` | HTTP（certbot 校验与跳转） |
| TCP | 443 | `0.0.0.0/0` | HTTPS |

3. **不要**对公网放行 `3005`（应用只给本机 Nginx 访问）。若临时直连调试，可临时加 `TCP:3005` 来源限你的 IP，用完删除。
4. 出站规则保持默认放行即可（需访问 GitHub、Let’s Encrypt）。

### 1.3 域名解析（`read.huatuo.cloud`）

1. 控制台 → **DNS 解析 DNSPod**（或你注册域名所用的解析产品）→ 找到 `huatuo.cloud`。
2. **添加记录**：
   - 主机记录：`read`
   - 记录类型：`A`
   - 记录值：CVM **公网 IP**
   - TTL：默认（如 600）
3. 保存后，本机执行 `ping read.huatuo.cloud` 或 `dig +short read.huatuo.cloud`，应返回该公网 IP。未生效前不要申请证书。

## 2. 服务器软件准备

SSH 登录（用户名按镜像，常见为 `ubuntu` 或 `root`）：

```bash
ssh ubuntu@你的公网IP
```

安装 Node.js 20+、npm、git、Nginx（示例用 NodeSource）：

```bash
sudo apt update
sudo apt install -y git nginx curl
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs
node -v   # 应 ≥ 20
npm -v
```

## 3. Clone 与配置

> **默认分支**：裸 `git clone` 会落到仓库的 Default branch。本仓库 Default branch 须为 **`main`**；clone 后执行 `git branch --show-current` 应显示 `main`。若不是，执行 `git checkout main && git pull`。

> **路径可自定**：下文 `/opt/reading-quotes` 仅为推荐示例，不是硬性要求。任意你有写权限的目录均可（如 `/home/ubuntu/reading-quotes`），只要 `.env`、`./deploy.sh` 与 Nginx `proxy_pass` 指向的都是**同一套实际路径**即可。

```bash
sudo mkdir -p /opt
sudo chown "$USER":"$USER" /opt
cd /opt
git clone https://github.com/huatuo-dr/reading-quotes.git
cd reading-quotes
cp .env.example .env
nano .env
```

必填（生产示例）：

| 变量 | 说明 |
|------|------|
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | 后台登录 |
| `SESSION_SECRET` | 长随机串 |
| `GIT_TOKEN` | 有本仓 `contents:write` 的 GitHub PAT（申请步骤见下文 [3.1 申请 GIT_TOKEN](#31-申请-git_token)） |
| `GIT_ENABLED` | 生产保持 `true` |
| `GIT_BRANCH` | 默认 `main` |
| `PORT` | **本指导示例：`3005`** |

可选：`GIT_REMOTE_URL`、`GIT_USER_NAME`、`GIT_USER_EMAIL`。

> 不要把 `.env` 提交进 Git。

### 3.1 申请 GIT_TOKEN

后台增删改摘抄后需要把 `data/quotes.json` **push** 回 GitHub，因此服务器 `.env` 里要配置可写本仓的 `GIT_TOKEN`。按下列步骤在 GitHub 创建（**不要把 token 发到聊天或提交进 Git**）。

#### Fine-grained token（推荐）

1. 浏览器打开 https://github.com/settings/tokens （登录你的 GitHub 账号）。
2. 选 **Fine-grained tokens** → **Generate new token**。
3. **Token name**：自定，如 `reading-quotes-deploy`。
4. **Expiration**：按你的安全策略设过期时间。
5. **Resource owner**：选你自己（或拥有该仓的账号）。
6. **Repository access** → **Only select repositories** → 只勾选 **`huatuo-dr/reading-quotes`**。
7. **Permissions** → **Repository permissions**：
   - **Contents**：**Read and write**（推送摘抄 JSON 必需）
   - **Metadata**：保持 **Read-only**（一般会自动带上）
8. 点击 **Generate token**，复制**只显示一次**的字符串。
9. 在服务器上写入 `.env`（与上文「必填」表中的 `GIT_TOKEN` 对应）：

```bash
# 在仓库目录编辑 .env
nano .env
# 设置：
# GIT_TOKEN=ghp_或github_pat_开头的那串
chmod 600 .env
```

#### Classic token（备选，权限更大）

1. 同一页面切到 **Tokens (classic)** → **Generate new token (classic)**。
2. 勾选 **`repo`**（整仓读写；公开仓长期使用不如 Fine-grained 最小权限稳妥）。
3. Generate 后同样只写入服务器 `.env` 的 `GIT_TOKEN=`，并 `chmod 600 .env`。

#### 注意

- Token 泄露后应立刻在 GitHub 上 **Revoke**，再生成新的并更新 `.env`。
- 生产环境保持 `GIT_ENABLED=true`；本地若不想自动 push，可在本地 `.env` 设 `GIT_ENABLED=false`（不要用生产 token 做无关实验）。

## 4. 部署与进程管理（`deploy.sh`）

`deploy.sh` 支持子命令。**无参数只打印帮助并以退出码 1 结束**，不会再默认跑全量部署。

| 命令 | 作用 |
|------|------|
| `./deploy.sh help` | 打印用法 |
| `./deploy.sh deploy` | 全量：`npm install --include=dev` → `npm run build` → 重启服务（install/build 不受 `.env` 里 `NODE_ENV=production` 影响） |
| `./deploy.sh start` | 未运行则启动（读 `.env` 的 `PORT`） |
| `./deploy.sh stop` | 停止服务（以**监听 PORT 的进程**为准，避免只杀掉 npm/npx 父进程） |
| `./deploy.sh restart` | 快速重启（**不**重新 install/build；先按端口停干净再拉起） |
| `./deploy.sh status` | 是否在跑、监听 PID、PORT |
| `./deploy.sh log` | `tail -f logs/app.log` |
| `./deploy.sh push` | 仅推送**已有**本地 commit（不自动 commit；读 `.env` 的 `GIT_*`） |

首次或依赖/前端有变更时用全量部署：

```bash
cd /opt/reading-quotes
./deploy.sh deploy
```

脚本会：`npm install --include=dev`（避免 `.env` 中 `NODE_ENV=production` 跳过 typescript 等构建依赖）→ `npm run build` → 后台以 production 启动服务（监听 `.env` 中的 `PORT`，示例为 **3005**）。启动成功后把**实际监听 PORT 的 PID**写入 `logs/app.pid`，日志在 `logs/app.log`。`stop`/`restart`/`status` 均以端口监听进程为准。

日常启停：

```bash
./deploy.sh status
./deploy.sh restart
./deploy.sh log
```

手动补推（例如网页改数据后 push 曾超时，本地已有 commit）：

```bash
./deploy.sh push
```

本机自检：

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:3005/
```

应返回 `200`。

## 5. Nginx 反代（HTTP）

先写仅 80 端口的站点配置（证书步骤见下一节）：

```bash
sudo nano /etc/nginx/sites-available/reading-quotes
```

内容示例：

```nginx
server {
  listen 80;
  server_name read.huatuo.cloud;

  location / {
    proxy_pass http://127.0.0.1:3005;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
  }
}
```

启用并重载：

```bash
sudo ln -sf /etc/nginx/sites-available/reading-quotes /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx
```

浏览器访问 `http://read.huatuo.cloud` 应能打开首页（此时仍是 HTTP）。

## 6. HTTPS：用 certbot 申请证书

前提（缺一不可）：

- 域名 `read.huatuo.cloud` 已解析到本机公网 IP  
- 安全组已放行 **80**（Let’s Encrypt HTTP-01 校验要用）  
- Nginx 已按上一节配置好 `server_name`，且 `nginx -t` 通过  

### 6.1 安装 certbot

```bash
sudo apt update
sudo apt install -y certbot python3-certbot-nginx
```

### 6.2 一键申请并写入 Nginx

```bash
sudo certbot --nginx -d read.huatuo.cloud
```

按提示：

1. 输入邮箱（用于到期提醒）  
2. 同意服务条款  
3. 是否分享邮箱可选  
4. certbot 会改 Nginx 配置：增加 443、证书路径，并通常把 80 跳到 HTTPS  

完成后访问：`https://read.huatuo.cloud`。

查看证书状态：

```bash
sudo certbot certificates
```

### 6.3 自动续期

Ubuntu 包装好的 certbot 一般带 systemd timer。检查：

```bash
sudo systemctl list-timers | grep certbot
# 或手动干跑：
sudo certbot renew --dry-run
```

续期成功后无需手工改 Nginx；失败时看 `/var/log/letsencrypt/letsencrypt.log`。

### 6.4 常见失败与处理

| 现象 | 处理 |
|------|------|
| Failed to connect / Connection refused on :80 | 安全组未放行 80；或 Nginx 未在跑：`sudo systemctl status nginx` |
| DNS problem / unauthorized | 解析未指向本机；`dig +short read.huatuo.cloud` 核对公网 IP |
| Too many certificates | Let’s Encrypt 有频率限制，稍后再试或用已有证书 |
| 证书好了但站点仍 HTTP | 确认 certbot 已改站点配置；`sudo nginx -t && sudo systemctl reload nginx` |
| HTTPS 打不开、HTTP 正常 | 安全组是否放行 **443** |

本仓库的 `deploy.sh` **不**申请证书、不改 DNS。

## 7. 更新代码

```bash
cd /opt/reading-quotes
git pull
./deploy.sh deploy
```

仅改后端/配置、前端已构建过时，可用 `./deploy.sh restart` 快速重启。

网页增删改会改 `data/quotes.json` 并自动 commit+push。若某次 push 失败留下本地 commit，之后再改一条摘抄或点「重试同步」时，即使工作区已干净也会继续 push 领先的 commit；也可手动 `./deploy.sh push`。`git pull` 前若有冲突需手工处理（见排障）。

## 8. 排障

| 现象 | 处理 |
|------|------|
| 无法登录 | 检查 `.env` 用户名密码；Cookie 是否被 HTTPS/域名策略拦截 |
| `tsc: not found` / deploy 构建失败 | `.env` 含 `NODE_ENV=production` 时旧脚本会跳过 devDependencies；请更新 `deploy.sh` 后重跑 `./deploy.sh deploy`，或临时 `npm install --include=dev && npm run build && ./deploy.sh restart` |
| Git 同步失败 | 后台点「重试同步」；或服务器上 `./deploy.sh push`；检查 `GIT_TOKEN`（需 Contents 读写）与分支保护 |
| push 冲突 | SSH 上 `git status` / `git pull --rebase` 后重试同步；避免 force |
| 端口占用 | 改 `PORT` 或结束旧 PID（`logs/app.pid`）；示例端口为 **3005** |
| 外网打不开但本机 `curl 127.0.0.1:3005` 正常 | 查 Nginx 与安全组 80/443，而不是对公网暴露 3005 |

## 9. 安全提示

服务器持有可写 token；请使用**最小权限** PAT，并保护后台密码。登录被盗意味着仓库可能被改写摘抄文件。不要把 `3005` 对公网长期开放。
